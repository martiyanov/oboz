## OBS-001. Графическая и количественная картина события: динамика источников и проверка распределения

**Статус:** идея / бэклог (не начато)
**Приоритет:** P2 (после стабилизации текущих фильтров и рейтинга)
**Оценка:** M1 — 0.5–1 день; M2 — 1–2 дня; M3 — 1–2 дня
**Зависимости:** история событий (сейчас её нет — есть только текущий срез и `.state/seen.json`),
часовой сбор снимков, страница рейтинга/аналитики.

### Зачем

Сейчас событие — это точка: «4 источника, score 0.92». Не видно, **как** новость набирала
источники: медленно и хаотично (естественная волна) или ровно, синхронно и одинаковыми текстами
(признак организованной кампании/вброса). Пользователь хочет графическую и количественную картину:
сколько новых источников прибавляется каждый час, как распределены публикации, есть ли аномалия.

Это не «детектор фейков» и не вердикт «новость проплачена» — только **признаки аномального
распространения** с объяснением, которые помогают читателю задать правильный вопрос.

### Что показываем (UI)

1. **Список событий с динамикой** (на странице `/rating` в блоке «Картина новостей» или отдельной
   `/analytics` — решить на этапе M3):
   - sparkline «новых независимых доменов в час» за 24–72 часа;
   - итог: всего источников, время до пика, доля источников вне первого часа;
   - аккуратный бейдж-подсказка: «ровное распространение», «синхронный старт», «естественная волна»,
     «мало данных».
2. **Карточка события**:
   - столбцы/область: новые домены по часам, с накоплением по тиру источника (A/B/C);
   - накопленная кривая уникальных доменов;
   - гистограмма числа публикаций по часам + наложенная базовая кривая (Gamma/lognormal) и
     отклонение (KS-расстояние);
   - таблица метрик: пик, скорость роста, «хвост», энтропия источников, доля почти одинаковых
     текстов, разброс времени публикаций;
   - пояснение: «почему алгоритм считает это необычным» — список вкладов признаков, без приговора.
3. **Сводка по региону/теме**: топ-5 событий по аномальности, распределение времени до пика,
   сравнение с базовой линией категории.

Тёмная/светлая темы, мобильный вид, доступность — как у остальных страниц. Графики — инлайн SVG
(без внешних библиотек, как везде).

### Метрики (количественная часть)

По каждому событию и часовому бакету `h`:

| Метрика | Что означает |
|---|---|
| `newDomains[h]` | новые независимые домены за час |
| `cumDomains[h]` | накопленное число уникальных доменов |
| `articles[h]` | число публикаций (включая дубли) |
| `tierMix[h]` | доли A/B/C среди новых источников |
| `domainEntropy` | энтропия Шеннона по доменам (разнообразие) |
| `hhi` | концентрация по холдингам/доменам |
| `nearDupShare` | доля почти одинаковых текстов (SimHash/MinHash) |
| `syncShare` | доля публикаций в окне ±15 минут от пика |
| `interArrivalCV` | коэффициент вариации интервалов между публикациями |
| `timeToPeak`, `decay` | скорость выхода на пик и затухания |
| `primaryLag` | есть ли ссылка на первоисточник и через сколько появилась |
| `dispersionIndex` | Var/Mean часовых счётчиков (1 = Пуассон, >1 — сверхдисперсия) |
| `ksToBaseline` | расстояние до базового распределения категории |

Аномальность — **объяснимый** композитный балл 0–100: сумма нормированных отклонений (robust
z-score по медиане/MAD) отдельных признаков с весами. Каждый вклад показывается в карточке.
Никаких «модель сказала» — только «вклад признака X = +18».

### Про распределения — важное уточнение

- Число публикаций/источников — **неотрицательные счётчики**, поэтому «нормальное по Гауссу»
  к ним напрямую не применяется: у них скошенное распределение. Гауссово приближение уместно
  скорее для **разброса времени** публикаций вокруг пика, а не для количества.
- Эмпирически число статей на событие часто описывают **гамма-распределением** (в модели
  compound Poisson–gamma / Tweedie: событие порождает пуассоновский поток, а число статей на
  событие — гамма), накопленное внимание — логнормальным. Это отправная точка для базовой линии.
- Признак «естественности» по Ашманову: суточный график естественного события — **хаотическая
  череда всплесков**, много разных авторов из разных мест пишут разное в разное время; у вброса —
  **очень ровный график** и синхронность. Но он же предупреждает: хорошо организованные кампании
  выглядят естественно и автоматическим анализом не ловятся — нужна проверка содержания.
- Поэтому в продукте формулировки: «признаки синхронной/ровной кампании», «аномальный профиль»,
  а не «заказная новость». И рядом — кнопка «посмотреть первоисточники».

### Статистический подход (MVP → точнее)

**M1 (данные):** часовые снимки, sparkline, описательные метрики, без выводов об аномальности.

**M2 (базовая линия и аномалии):**
- базовые распределения `newDomains[h]`/`cumDomains` по категории, городу и часу суток
  (медиана, MAD, квантили; минимум 20 событий в страте);
- для событий с ≥5 источниками — фит Gamma/lognormal (method of moments или MLE),
  KS/Anderson–Darling против базовой линии; для малых выборок — только robust z-score;
- детект всплесков: z-score по скользящему окну + упрощённый Kleinberg burst detection;
- синхронность: доля публикаций в узком окне и CV интервалов;
- композитный балл и ранжирование.

**M3 (UX и валидация):**
- страница/секция, графики, пояснения, легенда;
- проверка на синтетике: (а) естественная волна — Пуассон/гамма с шумом; (б) кампания — ровные
  публикации каждые 10 минут, одинаковые тексты; (в) breaking news — резкий пик;
- ручная разметка 30–50 реальных событий (естественные/скоординированные) для оценки
  precision/recall; без ground truth не обещать точность.

### Данные и пайплайн

- **Снимки:** часовой джоб (расширение `oboz watch`) пишет
  `.state/timeline/YYYY-MM-DD.jsonl`:
  `{ts, eventId, title, score, domains:[...], newDomains:[...], tiers:{A,B,C}, articles, topics, cities}`.
- **Идентичность события между часами:** стабильный ключ кластера (токен-хеш) + фаззи-сопоставление
  заголовков (Dice по токенам) для «дрейфующих» заголовков; хранить `firstSeen`, `lastSeen`.
- **Хранение:** JSONL + суточные агрегаты, ретенция 90 дней, gzip; при росте — SQLite/ClickHouse.
- **API:** `GET /api/timeline?event=<id>&hours=72` и
  `GET /api/analytics?region=&category=&city=&hours=24` (только агрегаты, без персональных данных).
- **Производительность:** агрегация на запись, страница читает готовые агрегаты; не считать
  статистику на каждый запрос.

### Этапы и критерии готовности

- **M1.** Часовые снимки пишутся ≥7 дней без пропусков; sparkline в списке событий; API timeline.
  Критерий: график совпадает с ручным подсчётом источников за час.
- **M2.** Графики в карточке, базовая линия, балл аномальности с вкладами; синтетические тесты
  (органическая волна vs ровная кампания) проходят; на реальных данных нет явных ложных
  срабатываний на breaking news (ручная выборка).
- **M3.** Раздел на странице, легенда «это не приговор», мобильный/темы; README и docs; оценка
  на размеченной выборке, зафиксированные precision/recall и ограничения.

### Риски и ограничения

- Ложные срабатывания: трагические/крупные события легитимно синхронны; малые выборки шумят.
- Скоординированные кампании могут имитировать естественность (Ашманов об этом прямо говорит).
- Мы не знаем владельцев и финансирование СМИ; концентрация по холдингам — прокси, не доказательство.
- Зеркала/перепечатки могут искажать число «независимых» источников (уже частично решается
  канонизацией доменов).
- Юридически/этически нельзя публиковать обвинения «новость проплачена» без доказательств:
  только «аномальный профиль распространения» + ссылки на источники.
- Нужна разметка для валидации; без неё — только эвристики.
